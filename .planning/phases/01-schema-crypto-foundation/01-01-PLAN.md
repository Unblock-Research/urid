<objective>
Migrate the Prisma schema to store every real-crypto field required by Phases 2–7, and add the LedgerTransaction table Phase 2 will use. All changes are additive and nullable so existing rows survive. Implements FND-01.

Because the database was provisioned with `prisma db push` (no migration history exists) but already contains data, this plan first BASELINES the current schema as an already-applied initial migration, then generates a second, additive migration for the new crypto/ledger fields. Skipping the baseline would cause `migrate dev` to detect drift and offer a destructive reset.

Purpose: Give every downstream phase a durable place to persist keys, signatures, Merkle roots, proof artifacts, shard material, and ledger transactions.
Output: Two migrations (baseline + additive) and an updated schema.prisma.
</objective>
