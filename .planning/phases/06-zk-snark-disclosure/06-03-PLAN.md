<objective>
Rewrite `ZkProofsService.prove()` and `verify()` to use the real Groth16 pipeline from Plan 02, replacing the fake proof.

`prove(credentialId, disclosedClaimName, threshold?, predicateEnabled?)` loads the credential (SoulboundToken), rebuilds its Poseidon-Merkle tree from the stored claims — reusing `crypto/claim-encoding.ts` + `crypto/merkle.ts`, PRE-PADDED to 16 leaves so the tree depth is exactly 4 — extracts the inclusion path for the disclosed claim, and calls `snarkjs.groth16.fullProve` with the committed `.wasm` + `.zkey`. It stores the real `proof`, `publicSignals`, `circuitId`, `disclosedClaims` (carrying the credential linkage), and `verified`, and deletes the legacy hash-of-request proof generation.

`verify(proofHash)` runs `snarkjs.groth16.verify(vKey, publicSignals, proof)` AND independently verifies the issuer's Ed25519 signature over the root (`root = publicSignals[1]`, per Plan 02's locked signal ordering) against the credential's stored `issuerPublicKey` — BOTH must pass, plus the root must match the stored credential's `merkleRoot` and `predicateResult` must be 1. Per the LOCKED constraint, the signature check stays OUTSIDE the circuit.

Purpose: Deliver ZKP-01 (real proof), ZKP-02 (snark + signature both required), ZKP-03 (non-member/tampered fails).
Output: rewritten service + adapted controller + the mandatory test suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → prove/verify endpoint | Untrusted credentialId, claimName, threshold, and proofHash cross into the service |
| prover → verifier | A submitted proof + publicSignals is untrusted until both SNARK and signature checks pass |
| stored proof → credential | The ZkProof row's claimed root must be bound to a genuinely-issued credential |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-07 | Spoofing | fabricated proof over an arbitrary root | critical | mitigate | verify() requires the Ed25519 issuer signature over the root AND `publicSignals[1]===sbt.merkleRoot` — a self-built tree has no valid issuer signature (ZKP-02) |
| T-06-08 | Tampering | swapped/mutated publicSignals or proof | high | mitigate | `snarkjs.groth16.verify` fails on any modification; tested by the tampered-publicSignals case |
| T-06-09 | Elevation of Privilege | non-member claim accepted | high | mitigate | prove() throws on absent claimName; circuit root constraint + root binding reject non-member roots (ZKP-03) |
| T-06-10 | Spoofing | proof re-use across a different credential | high | mitigate | Root binding: `publicSignals[1]` hex must equal the specific credential's stored `merkleRoot` |
| T-06-11 | Information Disclosure | leaking sibling claims via witness/logs | medium | mitigate | Private signals (leafValue, path) are never persisted or logged; only proof + public signals are stored |
| T-06-12 | Tampering | signature check bypassed (snark-only verify) | critical | mitigate | Both-must-pass logic; static/spec test asserts corrupted signature → valid:false even when SNARK verifies |
| T-06-13 | Denial of Service | fullProve blocks the event loop (~1-5s) | low | accept | Acceptable for local-real milestone; research flags worker-thread offload as a future optimization |
</threat_model>
