  <behavior>
    - canonicalize: same object with differently-ordered keys produces the identical string; nested objects and arrays are handled; array element order is preserved; primitives serialize as JSON.
    - GENESIS_PREV_HASH: a 64-character string of ASCII zeros.
    - computeTxHash({index,type,payload}, prevHash): returns a 64-char lowercase hex sha256 of (canonicalize({index,type,payload}) concatenated with prevHash); identical inputs yield an identical hash (deterministic); changing any of index/type/payload/prevHash changes the hash.
    - verifyChain(rows ordered by index ascending): returns valid=true for a correctly linked chain; returns valid=false with brokenAt set to the first index where either the recomputed txHash mismatches, the prevHash link is wrong, or the index is non-monotonic. Genesis (index 0) must link to GENESIS_PREV_HASH.
    - Tamper case: given a valid 3-row chain, mutating one row's payload and recomputing verification yields valid=false with brokenAt equal to that row's index.
    - Link case: building two sequential entries via the core produces row[1].prevHash === row[0].txHash.
  </behavior>
  <action>
    Create `packages/api/src/ledger/canonical.ts` exporting `canonicalize(value: unknown): string` — a deterministic JSON serializer that recursively sorts object keys (stable order), preserves array order, and serializes primitives as standard JSON. This is the single stable-key-order helper used for hashing (Claude's Discretion: self-contained here; no Phase-1 canonical helper exists to reuse).

    Create `packages/api/src/ledger/hash-chain.ts` — the pure, DB-free hashing core:
    - Export `GENESIS_PREV_HASH`: a fixed 64-character all-zeros hex string (self-describes the chain from row 0).
    - Export a `LedgerEntry` type `{ index: number; type: string; payload: unknown }` and a `ChainRow` type `{ index: number; type: string; payload: unknown; txHash: string; prevHash: string }`.
    - Export `computeTxHash(entry: LedgerEntry, prevHash: string): string` computing sha256 over the UTF-8 bytes of `canonicalize({ index, type, payload }) + prevHash`, returned as lowercase hex. Import `sha256` from `@noble/hashes/sha256` and `bytesToHex`/`utf8ToBytes` from `@noble/hashes/utils`.
    - Export `verifyChain(rows: ChainRow[]): { valid: boolean; brokenAt?: number }` that walks rows in ascending index order and, for each i, checks index === i, expected prevHash (i === 0 ? GENESIS_PREV_HASH : rows[i-1].txHash) matches rows[i].prevHash, and recompute of computeTxHash equals rows[i].txHash. Return the first failing index in `brokenAt`.

    Create `packages/api/src/ledger/hash-chain.spec.ts` covering every bullet in the behavior block (vitest; node env; colocated *.spec.ts). Write the failing tests first, then implement to green.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service caller → LedgerService | Business services pass payloads to be anchored; the ledger must persist an immutable, verifiable record |
| LocalLedgerService → LedgerTransaction table | Persisted rows form the tamper-evident chain; any post-hoc edit must be detectable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | LedgerTransaction rows | high | mitigate | Hash chain: txHash = sha256(canonical({index,type,payload}) + prevHash); verifyChain/verifyChainIntegrity recompute every hash and detect any mutated payload or relinked row (brokenAt) |
| T-02-02 | Repudiation | append ordering | medium | mitigate | Monotonic index + genesis-anchored prevHash chain gives a total, gap-detectable order of anchored transactions |
| T-02-03 | Tampering | concurrent appends (race on index/prevHash) | medium | mitigate | In-process promise-chain mutex + Prisma interactive transaction serialize appends so no two rows share an index or fork the chain (single-instance local-real target; documented) |
| T-02-04 | Information disclosure | payload stored in DB Json | low | accept | Local-real scope; payloads are non-secret anchoring metadata (handle/did/credential type). Production key custody is explicitly out of scope this milestone |
</threat_model>
