## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API controller → identity/credentials service | Client-triggered register/mint must not silently succeed when anchoring fails |
| identity/credentials service → LedgerService | Anchoring crosses into the ledger subsystem; failures must be observable to the caller |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Repudiation | register()/mint() silent anchor failure | high | mitigate | Delete the empty catch blocks; ledger failures reject the service call and propagate — no operation reports success when anchoring failed (asserted by failure-propagation tests) |
| T-02-06 | Tampering | onChainTxHash provenance | medium | mitigate | onChainTxHash is set from the ledger's returned real txHash (record.txHash), not a caller/mock-supplied value |
| T-02-07 | Spoofing/SSRF | outbound fetch to a hardcoded RPC URL | medium | mitigate | Remove the hardcoded port-9000 fetch entirely; anchoring now goes through the in-process LedgerService, eliminating the unvalidated outbound call |
</threat_model>
