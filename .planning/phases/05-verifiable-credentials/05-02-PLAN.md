<objective>
Turn minted SBTs into real verifiable credentials by wiring the wave-1 primitives into the credentials service.

1. Extend `mint()` to build a canonical claim set, commit it to a Poseidon-Merkle root, sign the root with the platform Ed25519 issuer key, and store `claims` + `merkleRoot` + `issuerSignature` + `issuerPublicKey` on the SBT — while preserving the existing `ledger.mintSbt(...)` anchor and `onChainTxHash` update.
2. Add `verifyCredential(id)` that recomputes the root from the STORED claims, compares it to the stored `merkleRoot`, then runs `Ed25519.verify(issuerSignature, merkleRoot, issuerPublicKey)` — returning false if any claim was mutated or the issuer key does not match.
3. Add a controller verify route and update/expand the credentials spec with all mandatory Phase 5 tests.

Purpose: Completes CRD-01 (signed commitment), CRD-02 (independent verification + tamper-evidence), and preserves CRD-03 (ledger anchor).
Output: Extended `credentials.service.ts`, a verify route in `credentials.controller.ts`, and a comprehensive `credentials.service.spec.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API (mint/verify) | Untrusted credential fields enter mint; verify is called by potentially untrusted relying parties |
| database → verifier | Stored claims/signature/public key are re-read at verify time and must be independently checkable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-02 | Tampering | verifyCredential vs stored claims | high | mitigate | verifyCredential recomputes the Merkle root from STORED claims (never from mint inputs); any mutated claim changes the root ⇒ returns false; spec asserts the mutate-title case |
| T-05-03 | Spoofing | issuer signature forgery | high | mitigate | Ed25519.verify(signature, rootMessageBytes(root), issuerPublicKey) against the stored issuer key; a signature not produced by the issuer private key fails; spec asserts the wrong-key case |
| T-05-01 | Information Disclosure | issuer private key in mint path | critical | mitigate | mint signs only via IssuerKeyService.sign; the private key never enters CredentialsService, logs, or the mint response — only issuerPublicKey/merkleRoot are returned |
| T-05-04 | Tampering | attacker rewrites BOTH stored signature and issuerPublicKey with a key they control | medium | accept | No issuer registry / trust anchor this phase (deferred — single platform issuer); self-consistent forgery via direct DB write is out of scope. Phase 6 verifiers should pin the known issuer public key as a trust anchor. Documented for the milestone. |
| T-05-SC | Tampering | npm dependencies | low | accept | No new packages installed; reuses audited @noble/* + circomlibjs from Phase 1 |
</threat_model>
