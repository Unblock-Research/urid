<objective>
Build the two reusable primitives Phase 5 mint/verify depend on, isolated from the credentials service so they can be tested in isolation and reused by Phase 6.

1. A claim-encoding module (`crypto/claim-encoding.ts`) that turns a credential's semantic fields into a canonical, key-ordered claim set and encodes each claim into a BN254 field element exactly as CRYPTO-NOTES.md section 3 prescribes. This encoder is the shared contract Phase 6's witness generator will reuse to produce identical leaves.
2. An injectable, env-backed platform Ed25519 issuer key provider (`crypto/issuer-key.service.ts`) that loads `ISSUER_PRIVATE_KEY` (hex) or generates a keypair at boot (logging only the public key), signs messages with the issuer private key, and exposes the issuer public key hex — without ever logging or returning the private key.

Purpose: Satisfies the encoder/signing half of CRD-01 and establishes the shared leaf-encoding + issuer-signing contract before the credentials service wires them together in wave 2.
Output: `claim-encoding.ts` (+ spec), `issuer-key.service.ts` (+ spec), and `crypto.module.ts` updated to register + export IssuerKeyService globally.
</objective>
